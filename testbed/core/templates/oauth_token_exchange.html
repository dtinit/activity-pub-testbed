Using the Access Token

A destination sends the token in the Authorization header of every request. For example, to fetch your Actor with its LOLA fields:

curl -H "Authorization: Bearer {{ token_response.access_token|default:"YOUR_ACCESS_TOKEN" }}" \
     -H "Accept: application/activity+json" \
     {{ activitypub_actor|default:"https:///api/actors//" }}

The LOLA Authorization Flow

  1. The destination sends you to the source's authorization endpoint with the activitypub_account_portability scope and a random state
  2. You approve on the source's consent screen, which names the account being granted
  3. The source redirects to the destination's callback with code, state and activitypub_actor, and the destination checks state matches
  4. This page: the destination exchanges the code for a token, authenticating with its client ID and secret (HTTP Basic)
  5. The destination reads your Actor and its migration collections with the token
